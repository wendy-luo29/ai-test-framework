## 5. 失败明细

### TC-ADDR-009 test_null_or_empty_key_fields

- 关联 AC：AC-02
- 现象：期望参数校验错误（`code=400`、`data=null`、`wrapper.success=false`）；实际 `wrapper.success=true`、`code="200"`、`data.success=false`、`data.reason="address not found"`、`data` 为对象。
- 请求：`POST /address/validate`，`state/postcode/suburb` 之一为 `null` 或 `""`。
- 响应：`{"data":{"success":false,"reason":"address not found","state":"","suburb":"Sydney","postcode":"2000",...},"code":"200","msg":"","success":true}`
- 归因：**C 脚本缺陷 + D 需求预期不一致**。实现把“字段存在但为 null/空串”当作查无匹配；把“字段缺失”当作参数校验错误。设计文档 v2.2 的规则过于笼统。
- 证据：本次 pytest 输出；主文件未生成 junit。
- 建议：TC-ADDR-009 改为断言 `address not found`；TC-ADDR-027 保留“字段缺失 → 参数校验错误”；同步修正设计文档。

### TC-ADDR-003 test_non_australia_country_rejected

- 关联 AC：AC-03
- 现象：`KeyError: 'msg'`。
- 请求：`POST /address/validate`，`country="ZZ"`。
- 响应：业务失败返回 `data` 对象；`assert_rejected` 在业务失败分支返回的是 `data` 字典，而调用方按 envelope 读取 `body["msg"]`。
- 归因：**C 脚本缺陷**。
- 证据：`tests/api/test_address_validate.py:115`；`utils/api_assertions.py::assert_rejected`。
- 建议：`assert_rejected` 在 HTTP 200 分支统一返回 envelope，再让调用方读取 `msg` / `data`。

### TC-ADDR-028 test_invalid_postcode_format

- 关联 AC：AC-07
- 现象：`KeyError: 'msg'`。
- 请求：`POST /address/validate`，`postcode` 为 `20A0` / `200` / `20000`。
- 响应：业务失败返回 `data` 对象。
- 归因：**C 脚本缺陷**，与 TC-ADDR-003 同一根因。
- 证据：`tests/api/test_address_validate.py:306`。
- 建议：同 TC-ADDR-003；修复后再补 reason 断言。
